# EpiData REC 数据文件与双录入比对

## rec 文件是什么

rec 是 EpiData 录入产生的**数据文件**（二进制、定长记录）：每条记录宽度 = 各字段掩码宽度之和，字段按 qes 定义顺序排列。qes 定义"长什么样"，rec 存"录了什么"。

- rec 由 **EpiData EntryClient** 从 qes 生成（不能由脚本直接产生）
- 文本字段按掩码宽度存定长字节（两_=一字 → 2 字节/字），GBK 编码
- 数字按位数定长，日期 `<dd/mm/yyyy>` 定长 10 字节，时间 `##时##分` 定长 4 字节
- 文件头部为 EpiData 版本信息（长度随版本而异），记录体紧随其后

## 字段宽度速查（与 qes 掩码一一对应）

| 掩码 | 宽度（字节） |
|---|---|
| `#` | 1 |
| `##` | 2 |
| `##.#` | 4（2 整数 + 小数点 + 1 小数） |
| `###########` | 11（电话） |
| `___…__`（两_=一字） | 字数 × 2 |
| `<dd/mm/yyyy>` | 10 |
| `##时##分` | 4 |

## 双录入比对（数据质量核心）

EpiData 推荐**双录入**：同一份调查表由两人各录一遍，比对不一致处回查原始问卷。本工具一次比对：

```bash
python3 scripts/rec_compare.py 录入1.rec 录入2.rec -f survey.json [-o 差异报告.txt]
```

- `survey.json`：与 qes/chk 生成时**同一份字段定义**（字段顺序、宽度必须与 rec 一致）
- 自动探测头部偏移；若你的 EpiData 版本头部特殊，用 `--skip-bytes N` 手动指定
- 输出：记录数、一致率、差异明细（记录号 + 字段名 + 两值）；退出码 0=完全一致，1=存在差异

### 比对规则

- 数字/文本统一**去首尾空白**后比较（EpiData 定长存储带填充）
- 记录数不一致时仅比对前 min(n1, n2) 条并提示
- 差异报告为 UTF-8 文本（CRLF），可直接给核查人员

## 局限与前提

- rec 为专有二进制格式，本工具按"定长记录 + 字段宽度"解析；**不同 EpiData 版本字段存储可能有细微差异**（如 3.x 与 4.x），首次使用请用一份已知内容的 rec 核对解析结果
- 字段定义 JSON 必须与生成 rec 的 qes 完全一致（字段数、顺序、类型）
- rec 生成、双录入本身请使用 EpiData EntryClient 完成（工具链只做比对质检）
