# EpiData REC 数据文件与双录入比对

## rec 文件真实格式（已用肺结核/禽流感/v3 标准格式 rec 实测校准）

rec 是 **文本格式**（GBK 编码 + CRLF），不是二进制：

```
567 1 Filelabel: 1                             ← 首行：定义区总行数 记录数 Filelabel: 标签长度
_LABEL1        1   2  30   0   0   0   0 112 附表1 流行病学调查表（禽流感病例）
#TEL1          1   4  30  27   4   6  11 112 TEL11.1联系方式：(1)电话：
#FOUNDTM       1   8  30  18   8   0   2 112 FOUNDTM发现时间：
#FOUNDTM1     20   8  30  22   8   0   2 112 时
…（共 N 行字段定义，N = 首行第 1 个数）
<数据区：定长字节流，每条记录宽度 = 全部非 LABEL 字段宽度之和>
```

**首行第 1 个数 = 定义区总行数（567），不是数据字段数**。567 = 389 真实字段 + 13 标题段 + 162 选项标签段 + 3 掩码中文段。

### 字段定义行

```
前缀字段名<空格填充> 类型 序号 30 起始 长度 小数 类型码 112 字段名+标签文本
```

| 列 | 含义 |
|---|---|
| 前缀 | `_`（字符/文本类段）或 `#`（数字类段） |
| 字段名 | 与 qes 一致（真实字段）；`_LABELn` 为显示段自动名；掩码中文段 = `字段名+数字`（FOUNDTM1） |
| 类型 | **≤10 = 真实数据字段；>10 = 选项标签段（_LABELn，文本为【1】男  【2】女 等）或掩码中文段（FOUNDTM1 等，文本为"时"）** |
| 序号 | 1-based 定义序号（与 qes 顺序一致） |
| 30 | 固定值（显示宽度参数） |
| 起始 | 段在记录中的起始位置 |
| 长度 | 存储字节宽 |
| 小数 | 小数位（数值字段） |
| 类型码 | **>0 = 数据字段；0 = 标题/说明段（章节标题、纯文本行）** |
| 112 | 固定前缀 |
| 字段名+标签 | 字段名重复 + 问题文本（GBK） |

### 掩码中文显示段（v3 实测新发现，rec_check 过滤的关键）

qes 掩码含中文（如 `##时##分`）时，EpiData 在 rec 定义区额外生成显示段：
`#FOUNDTM1 20 8 30 22 8 0 2 112 时`（类型 >10，文本为单个"时"字）。
**这类段不是数据字段**（qes 中无对应 `{FOUNDTM1}`），字段名 = 真实字段名+数字后缀，
极易被误当"rec 多出的字段"。rec_check 已按"类型 >10"自动过滤，不误报。

### 数据区

字段定义区结束后紧跟定长字节流：每条记录 = 字段宽度之和，字段按定义顺序排列、定宽切分（文本左对齐右补空格，数字右对齐左补空格），GBK 编码。**空数据库（仅建表未录入）时数据区为 0 字节**。

## 字段宽度速查（与 qes 掩码一一对应，实测验证）

| 掩码 | 宽度（字节） |
|---|---|
| `#` | 1 |
| `##` | 2 |
| `##.#` | 4（2 整数 + 小数点 + 1 小数；rec 类型码 101） |
| `###########` | 11（电话） |
| `___…__`（两_=一字） | 字数 × 2 |
| `<dd/mm/yyyy>` | 10（类型码 11） |
| `##时##分` | 4 |

## 双录入比对（数据质量核心）

EpiData 推荐**双录入**：同一份调查表由两人各录一遍，比对不一致处回查原始问卷。工具**自包含**（rec 内嵌字段定义，无需外部 JSON）：

```bash
python3 scripts/rec_compare.py 录入1.rec 录入2.rec [-o 差异报告.txt]
```

流程：
1. 解析两文件的字段定义（字段数/名称/顺序/宽度）
2. 字段定义不一致 → 报警并列出差异字段（退出码 2）
3. 一致 → 数据区按记录号逐字段比对（统一去首尾空白）
4. 输出一致率 + 差异明细（记录号、字段名、两值）；退出码 0=一致、1=有差异

### 边界情况

- 两文件均无记录（空数据库）→ 提示后正常完成（退出码 0）
- 记录数不一致 → 仅比对前 min 条并提示
- 文件含 GBK 无法解码的扩展字节 → 该字段值显示替换符，比对仍进行

## 局限与前提

- rec 由 **EpiData EntryClient** 从 qes 生成（不能脚本生成），本工具只做解析与比对质检
- 字段定义格式基于 EpiData 3.x 实测（肺结核 170 字段 / 禽流感 560 字段标准 rec）；4.x 或其他版本如有差异，先核对首行与字段定义行格式

## rec↔qes 结构校验（rec_check.py）

生成 rec 后建议先做结构校验，防止 qes 与 rec 字段错位/漏项：

```bash
python3 scripts/rec_check.py 调查表.qes 数据.rec [-o 报告.txt]
```

- 解析 qes 字段（`{}` 提取）与 rec 字段定义区（自动过滤宽 0 的 LABEL 标题字段与自动 ID 字段）
- 比对：字段数量、名称双向一致、顺序一致
- 退出码 0=一致、2=不一致
- **chk 与 rec 必须由同一份 qes 配套生成**：若 rec 字段名与 qes 不一致（如 FOUNDTM1 vs FOUNDTM），EpiData 会拒绝加载 chk（表现为"扫描不到 chk"）——先用 rec_check 排查字段差异
