# EpiData REC 数据文件与双录入比对

## rec 文件真实格式（已用肺结核/禽流感标准格式 rec 实测校准）

rec 是 **文本格式**（GBK 编码 + CRLF），不是二进制：

```
170 1 Filelabel: 11                          ← 首行：字段数 记录数 Filelabel: 标签长度
_LABEL1        1   1  30   0   0   0   0 112 肺结核流行病学个案调查表
#GBCODE        1   2  30  15   2   6   8 112 GBCODE国标码：
_FIRSTUNIT     1   3  30  44   3   1  30 112 FIRSTUNIT1.病例的首次发现单位：
…（共 N 行字段定义）
<数据区：定长字节流，每条记录宽度 = 全部非 LABEL 字段宽度之和>
```

### 字段定义行

```
前缀字段名<空格填充> 记录号 序号 30 标签字节长 序号 类型码 宽度 112 字段名 标签文本
```

| 列 | 含义 |
|---|---|
| 前缀 | `_`（文本类）或 `#`（数字类） |
| 字段名 | 与 qes 一致（首行第 2 个数） |
| 记录号 | 固定 1（定义区只写一次） |
| 序号 | 1-based 字段序号（与 qes 顺序一致） |
| 30 | 固定值（显示宽度参数） |
| 标签字节长 | 标签文本 GBK 字节数 |
| 类型码 | 0=LABEL/标题(宽0) 1=文本 6=数字 11=日期 101=小数 |
| 宽度 | 存储字节宽：文本=字数×2、数字=位数、日期=10 |
| 112 | 固定前缀 |
| 字段名+标签 | 字段名重复 + 问题文本（GBK） |

### 数据区

字段定义区结束后紧跟定长字节流：每条记录 = 字段宽度之和，字段按定义顺序排列、定宽切分（文本左对齐右补空格，数字右对齐左补空格），GBK 编码。**空数据库（仅建表未录入）时数据区为 0 字节**。

## 字段宽度速查（与 qes 掩码一一对应，实测验证）

| 掩码 | 宽度（字节） |
|---|---|
| `#` | 1 |
| `##` | 2 |
| `##.#` | 4（2 整数 + 小数点 + 1 小数；rec 类型码 101） |
| `###########` | 11（电话） |
| `___…__`（两_=一字） | 字数 × 2 |
| `<dd/mm/yyyy>` | 10（类型码 11） |
| `##时##分` | 4 |

## 双录入比对（数据质量核心）

EpiData 推荐**双录入**：同一份调查表由两人各录一遍，比对不一致处回查原始问卷。工具**自包含**（rec 内嵌字段定义，无需外部 JSON）：

```bash
python3 scripts/rec_compare.py 录入1.rec 录入2.rec [-o 差异报告.txt]
```

流程：
1. 解析两文件的字段定义（字段数/名称/顺序/宽度）
2. 字段定义不一致 → 报警并列出差异字段（退出码 2）
3. 一致 → 数据区按记录号逐字段比对（统一去首尾空白）
4. 输出一致率 + 差异明细（记录号、字段名、两值）；退出码 0=一致、1=有差异

### 边界情况

- 两文件均无记录（空数据库）→ 提示后正常完成（退出码 0）
- 记录数不一致 → 仅比对前 min 条并提示
- 文件含 GBK 无法解码的扩展字节 → 该字段值显示替换符，比对仍进行

## 局限与前提

- rec 由 **EpiData EntryClient** 从 qes 生成（不能脚本生成），本工具只做解析与比对质检
- 字段定义格式基于 EpiData 3.x 实测（肺结核 170 字段 / 禽流感 560 字段标准 rec）；4.x 或其他版本如有差异，先核对首行与字段定义行格式
